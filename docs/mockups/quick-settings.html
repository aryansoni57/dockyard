Quick Toggles: collapsed and expanded

Design exploration for the Quick Toggles tile. Two collapsed variants sit side by side in the dock; either one opens the same flyout above it. Everything below is clickable.

Collapsed variants

A Status strip, about 130 × 48

  • Four 18 px glyphs, no buttons inside: Wi-Fi, Bluetooth, DND, Night Light. Blue when on, ink at 42 % when off; off glyphs use the slashed icons.
  • The whole tile is one target that opens the flyout (Tile.qml clicked()). No toggle is one click away, but nothing can be flipped by accident.
  • Roughly 40 % of the current tile width. Reads like a menu-bar status cluster.
  • Open state: blue hairline and 14 % blue fill on the tile, so it is clear which tile owns the popup.

B Direct toggles, about 212 × 48

  • Today's row with chevrons removed: four 34 px round toggles plus the rounded-square panel button. Every pill is the same width.
  • One click flips a toggle in place; the grid button (or the tile gap) opens the flyout. The grid button turns solid blue while the flyout is open.
  • Mute moves into the flyout (speaker button on the volume slider), which saves one pill.
  • Roughly 70 % of the current width (5 round buttons instead of 2 split pills + 4 round).

Recommendation: B as the default, A as a "Compact" option in the config page. Both share one flyout and one ToggleSource, so offering both costs one extra delegate.

Expanded flyout

  • Surface. Opaque #1C1C1E / #FFFFFF, 360 px wide (over STYLE.md's 260–300 so "Do Not Disturb" fits on one line), 16 px radius, popup shadow from STYLE.md. Aligned to the tile's left edge, 8 px above the bar, clamped to the screen.
  • Toggle cards. 2 × 2 grid of 62 px cards in the second surface step. The icon circle goes solid blue when on (stronger than the dock's 20 % fill, because the popup is opaque).
  • Split targets. On Wi-Fi and Bluetooth, the circle toggles and the label area with the chevron opens the detail view. DND and Night Light toggle on the whole card.
  • Sliders. 24 px pill tracks, blue fill, white knob, tabular percent on the right. The speaker button mutes; a muted slider goes grey. Arrow keys step 5 %.
  • Detail view. Slides in from the right inside the same popup (160 ms), with a back button, a switch for the radio, sectioned rows and a settings pill in the footer. Height animates to fit.
  • Footer. Tertiary note on the left, "System Settings" pill on the right (systemsettings, or kcmshell6 kcm_networkmanagement / kcm_bluetooth from the detail views).

Motion

  • Open: fade, 6 px rise and scale from 0.98, 180 ms ease-out. Close: fade only, 120 ms.
  • Colour changes 120 ms; press scale 0.94 on buttons, 0.97 on tiles and cards, 80 ms.
  • Detail push and pop 160 ms. Nothing animates at idle.

New icons needed

sun, check, lock, close, chevron-left, headphones, keyboard, mouse, phone, plus a wifi variant with dimmable arcs for signal strength. They are drawn here in the same 24-unit, 2.1 stroke, round-cap style as contents/icons.

What ToggleSource must also expose

Today it has only booleans: wifiOn, btOn, muted, dndOn, nightOn. The flyout needs the values below. Fast values join the existing 5 s poll. Lists are fetched only while their detail view is open.

PropertyReadWrite
wifiSsid, wifiSignal nmcli -t -f ACTIVE,SSID,SIGNAL dev wifi | grep '^yes' n/a
wifiNetworks (detail only) nmcli -t -f IN-USE,SSID,SIGNAL,SECURITY dev wifi list --rescan auto plus nmcli -t -f NAME,TYPE con show for known networks nmcli con up id "<ssid>" (known), nmcli dev wifi connect "<ssid>" (open). Secured and new: hand off to the KCM.
btDevice, btBattery bluetoothctl devices Connected, then bluetoothctl info <MAC> for Name and Battery Percentage n/a
btDevices (detail only) bluetoothctl devices Paired plus info per device (Icon, Connected) bluetoothctl connect <MAC> / disconnect <MAC>
volume (0–1) Already polled: parse the number from wpctl get-volume @DEFAULT_AUDIO_SINK@ (Volume: 0.45 [MUTED]) wpctl set-volume -l 1.0 @DEFAULT_AUDIO_SINK@ 0.45, sent at most every 60 ms while dragging and once on release
brightness, brightnessAvailable busctl --user get-property org.kde.ScreenBrightness /org/kde/ScreenBrightness/display0 org.kde.ScreenBrightness.Display Brightness (and MaxBrightness) busctl --user call org.kde.ScreenBrightness /org/kde/ScreenBrightness/display0 org.kde.ScreenBrightness.Display SetBrightness iu <value> 0. Fallback: brightnessctl -m / brightnessctl set 40%
nightUntil busctl --user get-property org.kde.KWin /org/kde/KWin/NightLight org.kde.KWin.NightLight scheduledTransitionDateTime n/a (toggle already goes through NightLightInhibitor)
dndUntil Already there: notif.notificationsInhibitedUntil n/a

Possible cleaner sources, to check before adding shell code: the org.kde.bluezqt QML module for devices and battery, org.kde.plasma.networkmanagement models for networks, and the brightness plugin already imported in ToggleSource. The ScreenBrightness D-Bus path needs Plasma 6.2 or newer; check that on the target machine.

Open questions

  1. Which collapsed variant should ship as the default: A (status only, about 130 px) or B (direct toggles, about 212 px)? Should the other be a config option?
  2. Should mute stay in the collapsed row of variant B, or is the speaker button on the flyout's volume slider enough?
  3. Is the split card (circle toggles, label opens the list) clear enough, or should Wi-Fi and Bluetooth cards always open the list and toggle only from the switch inside it?
  4. Secured networks that are not saved need a password. Should the flyout open the Network KCM, or should it get an inline password field?
  5. Desktop with several monitors: one brightness slider for the primary display, one per display, or hide brightness when no backlight or DDC display is found?
  6. Should the flyout be the plasmoid's fullRepresentation (Plasma draws the dialog chrome) or a custom PlasmaCore.PopupPlasmoidDialog so it can match this surface exactly?
